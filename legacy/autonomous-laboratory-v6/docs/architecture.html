1. Backend service

Earlier versions opened the COM port directly from the browser using Web Serial. A persistent backend addresses three limitations of that approach:

LimitationConsequence
A COM port has one ownerA browser session prevents analysis scripts or another console from accessing the same serial device directly.
Measurement history belongs to one tabRefreshing or closing the tab discards its weight trace.
Automation depends on a browser sessionLong experiments and future spectroscopy or optimization loops need a service that continues independently of the page.
The backend owns the serial connection, so the browser is one of several possible API clients. Python scripts and future ML control loops can use the same HTTP interface. Access from another computer requires an explicit network configuration change.

3. Registered command handlers

Each operation is a registered function with parameter metadata. This gives validation, documentation, and interface hints a shared definition. The following excerpt illustrates registration and invocation; the full dosing implementation also enforces group ownership and a fixed 40 mL/min rate.

@function("motors.dose", "Dispense a specified volume", "motors",
          params=[Param("motor", "integer", label="Motor"),
                  Param("volume_ml", "number", label="Volume", unit="mL",
                        minimum=0.01, maximum=1000),
                  Param("direction", "integer", default=1, choices=[1, -1])])
def dose(ctx, motor, volume_ml, direction):
    # Simplified excerpt: see backend/functions/motors.py for the full handler.
    steps = volume_to_steps(ctx.config, volume_ml, motor) * direction
    sps = flow_to_sps(ctx.config, 40.0, motor)
    ctx.link.send(f"P,{motor},{steps},{sps}")
    return {"steps": steps, "sps": sps,
            "eta_s": round(abs(steps) / max(abs(sps), 1), 1)}
EndpointPurpose
GET /fnLists functions, parameters, and ranges used by the available-functions panel.
POST /fn/<name>Invokes a handler with a JSON object and returns {ok, result, elapsed_ms}
curl -X POST http://127.0.0.1:8000/fn/motors.dose ^
     -H "Content-Type: application/json" ^
     -d "{\"motor\":3,\"volume_ml\":2,\"flow_ml_min\":40}"
Handlers run in a persistent process. The service retains serial ownership across requests. The original design borrowed the function-registration style of FaaS, using small, independently described handlers. It does not deploy a container per request or require a serverless runtime.

Conflicting pins prevent startup.config.py collects pin assignments and checks for duplication. For example, assigning a valve to D22 conflicts with the driver pulse pin. The error identifies both assignments so the YAML can be corrected before operation.

5. Command and measurement flows

The interface receives streamed measurements rather than repeatedly polling for weight. Firmware starts the weight stream at 10 Hz. The backend updates cached state, appends to an in-memory history buffer, and broadcasts through SSE. A new browser session receives the same available history; restarting the backend clears that in-memory history.

Mass-feedback dosing uses the same measurement stream. The backend establishes a baseline, starts the pump, and reduces flow from 40 to 10 to 3 mL/min at remaining mass thresholds of min(2 g, 25% of target) and min(0.5 g, 5% of target). It stops at the configured tolerance and reports settled measurements. The ±0.5% tolerance is a control target, not a measured accuracy guarantee. Missing weight updates, a stalled mass increase, a total timeout, or a global stop abort the sequence. Targets are in grams, not millilitres.

7. Device extensions

Plasma spectroscopy is a planned extension to the v6 service. A new device handler would require configuration, an implementation, and registration:

StepChangePurpose
1Add to config/hardware.yaml a plasma: block for connection settings, integration time, and related parameters.
2Create backend/functions/plasma.py Use @function("plasma.acquire", …) to register acquisition operations and implement the device communication.
3In backend/functions/__init__.py import the new module. Importing the module registers its handlers.

GET /fn then includes the new handlers in the function list. A dedicated spectrum panel requires a frontend change. A new transport or firmware protocol also requires its own implementation and validation; registration alone does not provide spectrometer integration.

9. Troubleshooting

SymptomChecks
run.bat window closes immediatelyKeep batch files in Windows CRLF format. The launchers also use ASCII text to avoid code-page and byte-offset issues when chcp changes the console encoding. Preserve these settings when editing the launchers.
The console cannot reach the backendRun run.bat and check that the service terminal remains open and the server has not been stopped with Ctrl+C.
The console shows DisconnectedCheck the USB cable and close Arduino Serial Monitor. Then set an explicit YAML link.port and restart the backend.
A command times outCheck the firmware version. The expected startup line is READY,arduino+pump+2valves+scale
The weight panel shows an amber warningThe module is not responding. Check weight-module wiring, then run POST /fn/scale.diagnose {"mode":"scan"} only when all hardware is idle
The motor does not move and no error is reportedCheck driver ENA polarity, relay switching, and the 24 V supply.
A pin conflict prevents startupThe message identifies the conflicting assignments. Correct YAML, regenerate hw_config.h, and reflash firmware.
